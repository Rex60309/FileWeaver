# Phase 1 current-binary 100000-file observation

Measured 2026-11-09 04:22 UTC. Development evidence for the source in e2a68e0,
including Windows creation-time metadata reads. Not a release announcement or a
controlled cold-cache/performance-isolation experiment.

## Reproduce

```powershell
python benchmarks/search/benchmark_search.py --cli build/release/fileweaver.exe --core-runner build/release/search_core_benchmark.exe --cli-memory --build-info build/release/benchmark-build-info-Release.json --files 100000 --dataset nested-unicode --repetitions 5 --warmups 1 --storage-kind ssd --storage-model 'NVMe KINGSTON SKC3000S1024G' --output build/benchmarks/phase1-final-100k-20261109.json
```

## Conditions and correctness

- Intel Core i7-13700KF, 24 logical CPUs, 34104291328 bytes RAM.
- Windows 11 build 26300 AMD64; GCC 13.2.0 Release, C++20.
- Temporary fixture on the previously verified Kingston NVMe SSD. Storage label
  is operator supplied; the script does not auto-detect its physical backing.
- 100000 zero-byte multilingual files, 27 directories, 33334 distinct names,
  duplicate basenames across branches, result cutoff 100. CJK, accents and emoji.
- Six cases: three exact and three substring, including absent names, broad
  matches and deterministic cutoff ties. One first-observation round, one warmup,
  five measured rounds; 15 measured calls pooled per method/mode.
- All 168 timing samples and six extra CLI memory observations passed independent
  correctness checks. Generated-file count equaled the committed index count.
- Generation 39.9202348 seconds; initial CLI index 23.8054687 seconds. Timing
  includes CLI startup/JSON processing. Local verification processes overlapped
  parts of this experiment; no isolated throughput or before/after speedup claim.
- Fixture generation/indexing warms OS caches. No cache eviction; first-observed
  is not cold. The native method runs after the other baselines.

Native helper process peak working set through workload: 11292672 bytes. Extra
CLI observation pass: 6/6 available, maximum 10952704 bytes. These are whole-process
high-water marks, not per-query allocation or memory of the timed CLI processes.
The driver peak was 34058240 bytes. No content payloads are represented by the
zero-byte fixture.

Observed warm exact/substring p95 values are below SPEC's numerical targets on
this dataset/envelope. This does not establish universal target compliance, cold
latency, prefix/fuzzy performance, or 500k/1m behavior. Python methods and native
methods differ in runtime/envelope, so ratios are not isolated index speedups.
Existing SQLite B-tree helps exact equality; substring still uses a function
predicate. No specialized substring/trigram acceleration is claimed.
